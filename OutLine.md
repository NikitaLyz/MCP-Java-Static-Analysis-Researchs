## РОЗДІЛ 1. АНАЛІЗ ІСНУЮЧИХ ПІДХОДІВ ДО ВИЯВЛЕННЯ ДЕФЕКТІВ ПРОГРАМНОГО КОДУ З ВИКОРИСТАННЯМ СТАТИЧНОГО АНАЛІЗУ ТА ВЕЛИКИХ МОВНИХ МОДЕЛЕЙ

**1.1. Статичний аналіз програмного коду Java та його обмеження**

Принципи статичного аналізу, основні категорії дефектів, хибнопозитивні та хибнонегативні результати.

**1.2. Засоби статичного аналізу Java-коду: PMD, SpotBugs та SonarQube**

Призначення, принципи роботи, особливості виявлення дефектів і формати результатів трьох аналізаторів.

**1.3. Застосування великих мовних моделей для аналізу програмного коду**

Можливості LLM у виявленні дефектів, інтерпретації попереджень, поясненні причин помилок та генерації виправлень.

**1.4. Підходи до інтеграції LLM із зовнішніми інструментами**

Прямий виклик інструментів, агентні системи, принципи роботи Model Context Protocol, механізми опису та виклику MCP-інструментів.

**1.5. Огляд наявних досліджень і рішень, що поєднують LLM зі статичним аналізом**

Аналіз підходів IRIS, CORE, CodeCureAgent та інших досліджень використання LLM для аналізу, перевірки й виправлення програмного коду.

**1.6. Порівняння існуючих підходів та постановка задачі дослідження**

Визначення переваг і обмежень наявних рішень. Обґрунтування необхідності експериментального порівняння прямої інтеграції інструментів із їхнім використанням через MCP.

## РОЗДІЛ 2. РОЗРОБЛЕННЯ МОДЕЛЕЙ ІНТЕГРАЦІЇ СТАТИЧНИХ АНАЛІЗАТОРІВ ІЗ LLM ТА МЕТОДИКИ ЇХ ЕКСПЕРИМЕНТАЛЬНОГО ОЦІНЮВАННЯ

**2.1. Постановка задачі та формулювання дослідницької гіпотези**

Визначення мети порівняння, дослідницьких питань, основної та нульової гіпотез.

**2.2. Модель прямої взаємодії LLM із засобами статичного аналізу**

Розроблення архітектури, у якій LLM викликає PMD, SpotBugs і SonarQube через безпосередньо доступні програмні інструменти без використання MCP.

**2.3. Модель взаємодії LLM із засобами статичного аналізу через MCP-сервер**

Розроблення архітектури, у якій LLM використовує MCP-клієнт для виклику тих самих аналізаторів через розроблений MCP-сервер.

**2.4. Проєктування та реалізація MCP-сервера**

Структура сервера, інтерфейси інструментів PMD, SpotBugs і SonarQube, описи функцій, схеми параметрів, запуск аналізаторів, обробка помилок і формування структурованих результатів.

**2.5. Формування експериментального набору Java-програм**

Вибір тестових прикладів із Defects4J, Bugs.jar, Juliet та інших досліджень. Визначення еталонних результатів, категорій дефектів і критеріїв включення тестових прикладів.

**2.6. Визначення критеріїв оцінювання ефективності моделей**

Метрики правильності виявлення дефектів, хибних спрацьовувань, якості пояснень і виправлень, коректності виклику інструментів, часу виконання та використання токенів.

**2.7. Розроблення методики експерименту та розрахунку вартості**

Уніфікація умов тестування, вибір LLM, фіксація конфігурацій аналізаторів, кількості запусків, способів реєстрації результатів і визначення вартості кожного режиму.

## РОЗДІЛ 3. ЕКСПЕРИМЕНТАЛЬНЕ ДОСЛІДЖЕННЯ ЕФЕКТИВНОСТІ ПРЯМОЇ ТА MCP-ІНТЕГРАЦІЇ СТАТИЧНИХ АНАЛІЗАТОРІВ ІЗ LLM

**3.1. Організація експериментального середовища**

Підготовка наборів Java-програм, налаштування LLM, аналізаторів PMD, SpotBugs, SonarQube та обох варіантів інтеграції.

**3.2. Результати аналізу програмного коду за допомогою LLM із прямими викликами інструментів**

Проведення тестування першої моделі, реєстрація виявлених дефектів, результатів взаємодії з аналізаторами, часу та витрат.

**3.3. Результати аналізу програмного коду за допомогою LLM із викликами через MCP-сервер**

Проведення аналогічного тестування другої моделі за однакових умов із використанням розробленого MCP-сервера.

**3.4. Порівняльний аналіз точності та ефективності двох моделей**

Порівняння правильності виявлення дефектів, хибних спрацьовувань, якості пояснень, коректності викликів інструментів і стабільності результатів.

**3.5. Порівняльний аналіз часу виконання, використання токенів та вартості**

Оцінювання часу взаємодії, кількості викликів аналізаторів, обсягу переданих даних, витрат токенів і загальної вартості обробки тестових прикладів.

**3.6. Перевірка дослідницької гіпотези та оцінювання доцільності використання MCP**

Інтерпретація отриманих результатів. Визначення впливу способу інтеграції та деталізації описів інструментів. Встановлення умов, за яких використання MCP є обґрунтованим.
